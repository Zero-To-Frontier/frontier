# AI Frontier

AI 산업의 변화와 그에 따라 등장하는 오픈소스·도구를 살펴보며, 현재 생태계의 방향에 대한 관점과 질문을 쌓습니다.

Zero-To-Frontier는 변화의 방향을 탐색하는 Frontier와 오래가는 원리를 연구하는 Zero를 함께 운영합니다. 두 트랙은 각자의 흐름으로 진행하며, 주제를 매번 연결할 필요는 없습니다.

## 운영 방식

- 2주 동안 탐구하고 결과를 공유하며, Frontier와 Zero를 교차 진행하는 방식을 기본안으로 둡니다. 실제 일정과 준비 시간은 첫 모임에서 합의합니다.
- 함께 답할 질문과 공통 범위는 정하고, 각자의 접근 방법과 추가 탐구 깊이는 자율로 둡니다.
- 각 회차는 저장소 루트의 `YYYYMMDD/` 폴더로 관리합니다. 날짜는 결과를 공유하는 모임 날짜를 사용합니다.
- 개인 기록과 코드는 회차 폴더 안의 자기 이름 폴더에 남깁니다.
- 회차 안내와 회의록은 그 회차의 기록 담당자가 반영합니다. 담당자는 돌아가며 맡습니다.
- 발표 자료는 필수가 아닙니다. 질문 하나, 확인한 증거 하나, 남은 질문 하나를 준비합니다.
- 모임에서는 개인별 공유 후 접근법과 관찰의 차이를 토론합니다. 공동 결론에는 확인한 사실·미해결 사항·다음 질문을 남깁니다.
- 회차 폴더를 진행과 기록의 기준으로 사용합니다. Issues와 Projects는 필요할 때 도입합니다.

## 폴더 구조

아래 날짜와 이름은 구조를 설명하는 예시이며, 실제 회차 일정과 참여자를 확정한 것은 아닙니다.

```text
YYYYMMDD/
├── README.md        # 주제·공통 질문·일정·범위
├── 윤호/
│   └── README.md    # 개인 기록과 실험 코드
├── 동민/
│   └── README.md
└── meeting.md       # 공동 회의록과 결론
```

## 탐구 기준

1. 같은 산업적 질문 아래 각자 다른 오픈소스·도구·사례를 탐색합니다.
2. 등장 배경, 해결하려는 문제, 접근 방식, 한계를 살펴봅니다.
3. 핵심 동작이나 주장 하나를 직접 확인합니다. 매번 프로젝트 전체를 구현할 필요는 없습니다.
4. 여러 사례의 공통점과 차이를 모아 생태계에 대한 해석을 제시합니다.
5. 직접 관찰한 사실, 출처가 있는 주장, 개인의 추측을 구분합니다. 실행하지 못한 부분은 미검증으로 남깁니다.

최신 도구 목록이나 거대한 산업 전망을 매번 완성하는 것을 목표로 하지 않습니다. 작은 관찰을 누적하고 이전 판단을 수정합니다.
